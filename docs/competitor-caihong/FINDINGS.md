## 2. 从截图读出的关键产品细节

### 账号中心
- 双击已登录号 → 查看已有群/用户列表
- 开发者登录端配置：模拟「默认内置苹果桌面」等设备指纹
- 导入协议号 → 开始登录 两步；手机验证码登录会落 session
- 批量改名/头像/简介/用户名/二级密码
- 底部多开提醒：目录名从纯数字 1 编号

### 群发/加群
- `***` 分隔多条广告，单行模式随机抽一条
- 消息前/后随机字符数
- 定时起止；发送间隔建议 >10s；**完成本轮休息**（如 200s）
- 退出禁言群；禁言后暂停/去解封
- 组合发送 / 图文 / 文件视频；**PostBot 代码框**
- **以频道身份发广告**；**边加群边群发**（开任务前勾选）
- 加群：不重复、频繁等待、账号请求间隔（文档建议约 200s）
- 日志右键导出（上限约 2 万条）

### 私信
- 目标：`+手机号` / 用户名 / 已加群
- 同群发的随机话术与随机字符、PostBot
- **成功/失败分别写入** `logs/私信成功.txt`、`私信失败.txt`（可选时间戳）
- 线程数建议 ≈ 在用账号数

### 采集
- 普通群：按最近在线等状态筛
- **隐藏成员群**：从最近 N 条消息采「近 X 天发言用户」绕过隐藏列表
- 筛：有头像 / 会员
- 关键词搜群：多源（如「超级搜索」）；线程数可对齐关键词数；人数过滤交给「过滤筛群」

### 拉人
- **先设管理员（含加人权限）** 再拉；可批量设管/取消
- 「设置成公开链接」；群名改英文有时利于人数同步
- 停人上限、间隔、频繁等待；成功/失败 txt

### 炒群
- 一行一句话术，多号按行序轮流发；空话术=只加群
- 间隔区间 + 无限循环

### 过滤筛群
- 按人数区间；权限：可发文字+链接 / 图 / 视频；排除频繁群
- **筛掉有机器人管理的群**
- 导出账号已加公开群；「分组链接一键加群」格式更稳

### 综合功能
- 从频道/群历史抽 **链接 / @提及**（默认扫 1000 条）
- 批量向 @SpamBot 提交解封话术
- TData→session（勿用 Portable 打开过的 tdata；转完重启 MsgServer）

### 隐藏转发 / 名片贴纸
- 自有双公开频道：主频道发内容 → 回复到关联频道 → 用关联频道消息链转发并勾「隐藏来源」
- 名片：对方需开启「手机号可被搜索」→ 分享到自有公开频道 → 复制消息链 → 转发+隐藏来源
- 贴纸同理（先发到公开频道再转发）

### PostBot（[原文](https://docs.tgcaihong.com/qun-fa-si-xin-jie-chu-deng-dai-pin-fan-postbot-an-niu)）
- Create post → Text/Photo/GIF/Video → 可选按钮 `[文案 + https://…]` → Ready → 复制代码进软件
- **一旦填了 PostBot，其它文案/媒体配置全部失效，只发代码**

### 广告中文标签（≥3.72）
`[加粗][斜体][下划线][删除线][剧透][引用][等宽][链接=url][代码块]`（等宽/代码块不可与其它标签叠用）

### 群发 FAQ 共识
1. 加群/群发间隔宜长（例 200s/群），否则 FloodWait 数分钟～数小时甚至死号；PostBot 可缓解
2. 老号更耐用；少带链接和敏感词
3. **必须 session+json**；会员号更耐用
4. 私信先用「你好」测额度再换广告
5. 多国号对照测试差异大
6. 没有绝对不封

## 3. 对照 TelegramTools：已有 / 可借鉴 / 可跳过

### 已大致持平（不必跟抄 UI）
账号导入登录、群发加群、私信、采集搜群、拉人、炒群、监控回复、筛群、PostBot、独立广告、tdata、隐藏转发、SpamBot、中文富文本标签、多开数据目录、试发/PeerFlood 处理

### 高价值可借鉴（建议排期）

| 优先级 | 项 | 理由 |
|--------|----|------|
| P0 | PostBot 互斥提示（填了则忽略其它文案） | 竞品文档反复强调，用户最易踩坑 |
| P0 | 私信/拉人成功失败分文件导出（可带时间戳） | 运营闭环；我们已有失败明细，差批量落盘 |
| P1 | 群发「完成本轮休息」+ 循环 | 无人值守连续跑 |
| P1 | 「边加群边群发」 | 竞品主打工作流 |
| P1 | 消息前后随机字符 + `***` 多话术随机 | 降重复检测，文档与 UI 都主推 |
| P1 | 隐藏成员群：按近期发言采用户 | 文档明确踩坑：隐藏列表采不到 |
| P1 | 筛群：可发图/视频/链权限 + 无 Bot 管理 | 降低白发/秒封 |
| P2 | 拉人：批量设管 / 设公开链向导 | 文档写「非管理拉不动」 |
| P2 | 综合：历史抽链接/@ | 供需群线索场景 |
| P2 | 定时起止群发 | 错峰 |
| P2 | 退出禁言群 / 禁言策略 | 少浪费配额 |
| P2 | 设备指纹可选（Desktop/iOS 等） | 防「公用客户端指纹」 |
| P2 | 协议号→官方客户端接码向导 | 文档独立成篇，客服向刚需 |
| P3 | 以频道身份发送 | 部分群允许频道身份 |
| P3 | 代理端口预设芯片（Clash/V2ray…） | 降上手成本 |
| P3 | 服务器/号量容量说明写进启动文档 | Vultr 那篇的运营经验 |

### 可弱化或跳过
- Defender / 易语言乱码：我们是 Tauri+Python，不吃这套坑
- MsgServer 通信：架构不同
- 复制整包多开编号目录：我们已有 `TELEGRAM_TOOLS_DATA`，文档写清即可
- Vultr 推销本身：只借鉴「号量 vs 内存」经验，不必内嵌厂商教程

## 4. 结论（一句话）

竞品文档的价值不在新模块名，而在：**工作流（边加边发、轮休、设管再拉）、风控细节（随机字符、PostBot 互斥、隐藏成员发言采、筛权限/Bot）、以及落地产物（成功失败 txt、一键加群链接格式）**。优先补这些，比再堆实验功能更接近他们「能跑起来」的体验。
